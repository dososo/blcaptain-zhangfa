# 章法

**让中文网页，有自己的章法。**

`blcaptain-zhangfa` 是面向中文网页的设计与验收技能。它用真实内容决定结构，保全已有功能，结合分寸测量中文，再分别记录技术结果、设计意见与人工验收。

适用于 Claude Code、Codex 等能读取 `SKILL.md` 的智能体。支持新建、受限改版和只审阅；首版专注网页。

## 看效果

[打开案例试验场](https://dososo.github.io/blcaptain-zhangfa/) · [12组局部试排](https://dososo.github.io/blcaptain-zhangfa/lab/) · [方法与边界](docs/方法与边界.md) · [生成与评测协议](bench/协议.md)

试验场逐题切换“不加载本技能／仅分寸／章法＋分寸”，支持桌面与手机宽度预览、查看原始需求和打开真实页面。规则示意、实际生成和未完成状态分别标注。

这里展示的是批次生成示例，不是每题独立运行的统计胜率实验。完整模型构建版本、统一 token 成本等无法核实时明确披露；不宣称视觉胜率或业务转化提升。技术检查也不等于审美或真机验收。

已生成24个场景、三种条件的60个页面与12份审阅报告，另有12组手工局部示意。部分加载章法的批次未完整执行方向比较或先片段试排，偏差与额外修复在场景内直接披露；不能将它们当作完整技能流程的严格对照。生成记录脱敏副本保留时间、操作、失败和产物哈希；本机绝对路径与原始二进制截图不随这些记录分发。

## 它改变哪些决定

- **内容先于风格。** 阅读、购买、比较、管理与展览按不同任务组织，不默认同一个落地页骨架。
- **中文参与构图。** 用真实标题、混排、单位与长文本试排，再决定容器、字体和阅读节奏。
- **风格服务信息。** 主对象可以是产品、作品、表格、图表或文字；不把渐变、系统字体、卡片一律禁用。
- **保全可运行行为。** 改版前后核对字段、路由、状态与关键任务；只审阅模式不修改源码。
- **交付有证据。** 规则通过、浏览器任务、独立模型意见和人类验收分别报告。

## 安装

先克隆仓库，选择一个工具的项目目录安装，不需要修改全局配置：

```bash
git clone https://github.com/dososo/blcaptain-zhangfa.git
```

Codex：在你的项目中准备 `.agents/skills/`，把本仓库的 `skills/blcaptain-zhangfa` 整个目录复制进去。Claude Code：复制到项目的 `.claude/skills/`。如已有同名技能，先比较内容，不直接覆盖。

也可以从版本页下载技能 ZIP，解压后将整个 `blcaptain-zhangfa` 目录放进相应技能目录。需要包括 `references/`、`scripts/`、`agents/`、`LICENSE` 与 `NOTICE`，不能只复制入口文件。

重启或重新加载相应工具后，确认技能可发现。调用示例：

```text
使用 $blcaptain-zhangfa 给这个中文活动页做受限改版。
保留日期、票种、条款和报名行为，先检查现状，再提出结构与排版改进。
```

Claude Code 可以用 `/blcaptain-zhangfa` 加需求；也可以直接说“用章法审阅这个中文页面”。是否自动触发由宿主工具的技能机制决定，不能只凭文件复制就推断已加载。

卸载时移走本次复制的这个技能目录即可，不需要更改项目代码、浏览器、代理或其他技能。

## 使用分寸与浏览器检查

设计指令本身不需要浏览器；要取得实际中文度量和截图，项目中需要 Node.js 20.19 或更高版本、系统 Chrome，以及项目本地依赖：

```bash
npm install --save-dev measure-cjk@0.1.0 playwright-core@1.64.1
```

这条命令会联网并修改当前项目的依赖文件；已有项目应先检查其安装方式与约定。检查器不会自动执行安装或升级。

先启动你的页面，再从你的项目目录运行：

```bash
node <技能目录>/scripts/check-page.mjs --url http://localhost:5173 --out evidence/zhangfa
```

`<技能目录>` 替换为安装目录的绝对路径，端口换成项目实际端口。查看完整参数：

```bash
node <技能目录>/scripts/check-page.mjs --help
```

它检查指定宽度下的部分溢出、文字裁切、损坏图片、常见控件名称与页面异常，再调用固定版本分寸。报告与截图写入证据目录，每轮单独保存；根 `report.json` 指向最新结果。

项目存在 `measure.config.json` 时保留其规则。分寸 0.1.0 要求配置与证据在同一根内，因此证据目录应放在项目内；冲突时明确返回未知，不改默认阈值。

默认仅访问回环地址。远端网页需显式 `--allow-remote`；该选项也允许远端资源。只使用已有环境，不写全局配置、不启用遥测、不上传检查结果。

| 状态 | 含义 |
|---|---|
| `pass` | 请求范围的自动检查已执行并通过 |
| `fail` | 有可定位的失败 |
| `not_run` | 未执行或缺环境 |
| `unknown` | 不能可靠判断 |
| `not_applicable` | 确认不适用 |

CLI 退出码为 0（自动检查通过）、1（页面或规则失败）、2（环境、参数、未知或未运行）。人工视觉、语义断行、复杂读屏与真机状态仍单独保留 `MANUAL_PENDING`。

## 本地查看、验证与打包

```bash
npm ci --ignore-scripts
npm run serve
npm test
npm run verify
npm run pack:skill
```

预览地址为 `http://127.0.0.1:4179`。测试需要系统 Chrome。技能包生成在 `release/`，包含校验和；相同内容生成相同 ZIP。研究档案、缓存、内部任务与本机运行原始日志不进入技能包。

案例、生成条件和实际检查范围见 [生成协议](bench/协议.md)。示例中的机构、人物、商品、价格、日期与数据均为合成演示内容，不代表真实背书或业务。原型成功只表示本地模拟操作完成。

不分发第三方字体文件。字体的系统调用、自托管、图片输出和文件再分发分别核验；分寸授权表提供原文链接与核验日期，未知内容不作承诺。

章法不保证某种风格必然更美、业务转化提升、排行榜表现或任何流行程度。欢迎带着可复现任务、中文长文本与失败证据贡献改进。
