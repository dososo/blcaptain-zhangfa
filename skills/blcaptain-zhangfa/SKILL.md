# 章法

让中文网页，有自己的章法。用真实中文内容决定页面结构，再用运行结果检验它。

中文项目默认使用中文界面与说明，代码标识和必要原文保留；用户明确要求其他语言时遵循其要求。

本技能组织页面表达；分寸 `measure-cjk` 提供中文排版的可测量依据。规则符合性、视觉判断、人工体验是不同的结果，分别报告。

## 先判断这次要做什么

| 模式 | 做法 | 完成依据 |
|---|---|---|
| 新建 | 确定访客任务与内容，比较结构，再实现一个入选方向 | 方向取舍、真实内容片段、可运行页面与主任务证据 |
| 受限改版 | 先记录现有行为与允许修改范围，保全功能后改视觉 | 修改前基线、同任务改后结果、受保护内容与行为对照 |
| 只审阅 | 运行和观察，不修改源文件 | 实际看过的页面与状态、可定位的问题和未覆盖范围 |

开始时用几句话说明本次模式、访客主任务、保留项、准备验证的路径与宽度；已有约定直接复用，不把它变成额外审批。执行中范围变化时更新约定。不同模式的最小证据与可简化范围见[验收协议](references/验收协议.md#按模式保留最小证据)。

局部修复沿用既有品牌与组件，不把一个按钮问题升级为全站重设计。没有设计文件不等于没有既有设计系统。

按任务读取参考，不必全部加载：

- 信息结构、方向选择或改版：读 [页面任务](references/页面任务.md)。
- 中文标题、长文、混排、字体或移动布局：读 [中文构成](references/中文构成.md)。
- 浏览器检查、分寸命令、交互与交付：读 [验收协议](references/验收协议.md)。

## 因文成形

### 一、明事：锁定事实与任务

先用已有资料确定：访客是谁、来这里解决什么、主要动作是什么、哪些内容和行为不能丢。缺失信息会改变设计时才询问；能合理推进时公开假设并继续。

把素材区分为已核实资料、用户提供内容、明确标记的演示数据、待补内容。保留真实数字；没有客户、评价、销量或合作品牌，就不要补造。原型不冒充已接入真实业务。

文案不是随意调整的布局材料。用户锁定文字时，通过排版解决；确有必要缩短或改写，先说明冲突并确认。演示内容同样要保持前后一致。

### 二、成章：按决策顺序组织页面

先决定访客需要先知道什么、比较什么、最后做什么，再确定区块。阅读、购买、检索、管理与展览不应共享一套默认落地页骨架。

方向尚未确定且需要探索结构的新页面，先比较两到三个关键片段或首屏，随后只深化入选方向。方向须在信息结构、中文排印、视觉主对象中至少两项不同；用户已指定方向、修小问题或品牌内迭代时不强制多选。

每个方向用一句话解释“这个结构如何服务任务”，展示足以判断的真实中文片段及其窄屏变化。先确定主对象、阅读路径与主要动作，再选装饰；不要仅靠换颜色或字体制造三个选项。

方向比较须有可回看的片段、草图或运行页面，不以事后文字声称“已经比较”代替。用户已定方向时，直接试排该方向的关键内容；局部修复只复现并检查受影响片段，不另造整页方案。因范围或工具限制省略试排时，写清省略项、理由与剩余风险；加载过技能不等于完整执行了流程。

### 三、量字：先试排真实中文

用真实标题、导航、按钮、正文和数据做关键片段，观察实际字体、行盒与边界。英文词数、字符长度和 `ch` 不等于汉字实宽。

检查长标题的专名、语义断点与孤字，数字和单位的关系，窄屏长按钮、公司名、网址和表格。语义是否自然需要评审，机器几何警告不能直接决定文案。

断行先调整容器与排列，再处理少量语义片段，最后微调字号；长专名需要可读的分段，不能整串锁定不换行。自动均衡不能保证中文语义自然。窄屏按内容重排，不把桌面整页缩成小字，也不靠隐藏或裁切消除溢出。具体取舍见[中文构成](references/中文构成.md)。

完整页面铺开前，先在关键桌面与窄屏宽度检查标题和主要动作。检查器的 `pages[].headings[].lines` 提供真实行片段：逐行读一遍，关注短语被拆开或末行无意孤字。先解决影响理解的构图问题，不要把修复预算全部花在低影响机器警告上。该探针只观察前12个可见横排标题，不自动判断语义。

把分寸测量放进试排与迭代，不只在交付前补一次。若规则、品牌约定和用户要求冲突，明确范围与理由，不静默关闭规则或改阈值凑通过。

### 四、造境：确定视觉主对象

选择最能解释内容的对象：真实产品、作品、地图、图表、表格、界面或中文排印。素材不足时用文字与结构建立主次，不用虚假背书填空。

中文设计也包括现代科技、日常商业、精密数据和无图页面。不要自动套宣纸、印章、宋体；同样不要把系统字体、渐变、卡片或圆角一律判错。判断它们在这一页是否承担信息职责。

设计首屏时回答：先看见什么、为什么继续看、下一步做什么。建立可延续的字号、对齐、间距与色彩职责，再让内容的真实转折形成疏密变化。鲜明不等于把所有元素都放大；删除无信息作用的装饰，保留一个属于内容的记忆点。详见[页面任务](references/页面任务.md)。

动效只服务操作反馈、状态连续或必要叙事。内容默认可读，尊重减少动态效果的偏好，不用动画替代信息层级。延迟加载、脚本或字体失败时，保留关键内容的可读性或可理解的失败状态；主要动作不可用时说明限制与继续路径，不伪装成功。不为第一眼效果牺牲阅读与操作。

### 五、验真：运行页面与主要任务

先确认截图来自本次版本和正确路由，字体与图片达到可观察的稳定状态。保存 URL、视口、状态、工具版本与证据路径。旧截图、空白截图和未加载资源不能作为新页面证据。

运行分寸和必要的浏览器检查；保留原始报告。对交互页面至少在最窄受支持宽度实际完成一次主路径，观察结果状态并检查错误恢复；提示、校验、操作结果和模拟边界应互相一致。改版需复核旧行为；只审阅不得写回项目。

浏览器不可用时仍可交付代码或静态意见，但将浏览器、断行与交互检查记为未运行，列出恢复验证所需条件。预算不足时优先保全内容与主任务，披露剩余检查；不把计划、截图文件存在或脚本退出码当成实际看过页面的证据。

工具入口：`scripts/check-page.mjs`，先读 `--help`。它只检查部分客观问题，不给审美分，不代表完整无障碍合规。缺依赖、超时和未知结果都要明确保留。

### 六、复核：设计与机器证据分别判断

先让审查者看任务、内容和有效产物，不给作者的解释或机器分数；再对照检查报告，解决分歧。具备授权与可用子代理时可独立审阅；否则写明为同会话自审，不冒充独立评审。

实际打开桌面与窄屏截图，检查首屏、正文密集处和主要操作状态；不能只读源码、DOM或机器报告完成视觉审查。评审回答：页面在讲什么、动作是否明确、中文是否自然、主对象是否属于这个内容、功能或信息是否丢失。优先修影响最大的具体问题，不为了显得专业凑清单。修后按同一视口、内容、状态与锚点复查，比较收益和退步。公开精选案例须说明筛选范围；后期人工修复另列，不能回写原始生成结果或用它计算技能生成胜率。

模型评审不等于真实人类测试，模拟手机视口不等于真机。未经人工体验的部分标记 `MANUAL_PENDING`。

## 交付格式

按变更规模简短报告：

1. 做了哪些可检查的行为，对应哪些文件或组件。
2. 运行了什么命令或任务，实际结果与证据在哪里。
3. 哪些是推断、未知、未运行、不适用或仍失败。
4. 人工视觉与真实设备验收状态，以及最小回滚范围。

交付前对照开始时的约定：每项注明已执行的结果、未运行、未知、不适用或仍失败，并指向实际产物；先前证据在修后未重测时写明对应版本。小修改可用一段话完成，不强制生成新文档。

只有真正执行并通过的项目才写“通过”。不能以静态检查退出 0 代替浏览器验收，也不能以规则零错误宣称更美观或业务提升。

## 保持技能轻量

复用当前项目的框架、设计系统和测试设施。仅为当前任务生成必要文件；不默认安装全局工具、写全局记忆、修改钩子或上传项目数据。项目已有决策记录时更新原文件；没有实质变化不创建新记录。
