# 中文构成与真实测量

## 先确定语言与文字角色

简体、繁体及地区字形分别处理；根语言标记和局部语言不能随便混用。中文设计不等于日文、韩文的排版规则已经覆盖。

标题、正文、说明、按钮、导航、数字和代码各自有职责。正文的阅读行长不能直接作为按钮、表格或展览标题的硬限制。

## 中文内容如何进入布局

1. 用真实内容试排，不先用短占位字完成布局再替换长标题。
2. 观察实际文本行、边界与溢出。字符长度只能用来发现压力内容；不能证明最终宽度。
3. 改容器、字号阶梯、主次与排列，再复测；用户锁定文字时不擅自删词。
4. 语义断行由人或设计评审判断。自动脚本能发现末行极短，却不知道这是不是有意的强调。

标题不要把人名、作品名、型号、币种或单位拆成难以理解的碎片。少量局部不换行可保留语义，但不能把整段变成一块导致手机溢出。

正文限宽以实际阅读为准。分寸当前默认推荐约 28–40 个汉字行长、较宽松的正文行高；这是可调整的项目规则，不是全部字体、年龄与界面的通用科学阈值。窄屏无需为了满足最少字数而缩小字体。

## 混排与标点

遵循项目确定的标点和引号风格；代码、URL、数字格式与引用原文不套用全文替换。

中西文间距可采用浏览器排版能力或项目既有文本规范。新 CSS 能力需要确认实际支持，不支持时保持可读降级。不要为了增加间距破坏可复制命令、账号、文件名或型号。

检查闭合标点出现在行首、起始标点落在行末、成组符号被拆开。几何检查和声明 `line-break` 是不同证据；没有观察真实断行时不能说问题已经消失。

避免通篇 `word-break: break-all`、整体 `white-space: nowrap` 或根元素裁切去隐藏问题。代码块和宽表格可局部滚动，并让用户知道还有内容。

## 字体决策

先选字体角色，再决定具体字族。中文标题可以是黑体、宋体或其他有证据的选择；中后台使用系统界面字体是正常做法。只更换拉丁字族不等于改变中文字体。

通过 `measure-cjk fonts` 查询已收录字体的授权、原文链接与核验日期。系统调用、自托管、商业图片输出、字体文件再分发是不同权限。未收录或原文不清楚时写未知，不自行承诺。

不要把操作系统随附字体文件拷贝进开源仓库。需要可分发字体时核验具体版本与许可；可以使用系统字体栈而不携带字体文件。

检查字号、真实字重、缺字和回退。`font-synthesis` 声明不能证明实际加载了所需字重；`font-family` 计算值也不能证明每个汉字由该字体渲染。必要时用浏览器字体诊断；没有该能力就说明未验证。

## 三种字体状态

| 状态 | 要观察的内容 |
|---|---|
| 首次加载 | 文字是否可读、重要动作是否可用 |
| 加载完成 | 实际断行、字重、对齐、元素边界 |
| 字体失败 | 后备字体是否缺字、溢出或遮挡动作 |

`document.fonts.ready` 是截图稳定条件之一，不代表字体授权已核验或所有预期字体都成功命中。大体积中文字体按需求评估分片、子集和预加载，避免整套多字重默认下载。记录实测成本，不凭文件扩展名猜性能。

## 压力内容

使用长正式机构名、双行按钮、书名号与括号、连续破折号、省略号、英文缩写、`3.5mm`、`¥1,280`、日期、版本号与长链接。冻结这些内容后，在窄屏、放大、字体失败与用户覆盖文字间距的状态下检查。

金额或参数需要纵向比较时，可使用 `font-variant-numeric: tabular-nums`，但要观察实际字体是否支持和对齐。不要为了“真实感”把整数改成带小数的虚构指标。
