# 页面任务与结构

## 用一句话确定成功

“这位访客在这个场景，需要理解或完成什么？”答案应该能检查，例如找到合适房型、理解一项规格差异、定位安装错误、提交一份本地演示表单。抽象的“高级、科技、有设计感”不能单独构成成功标准。

| 任务 | 优先安排 | 适合的主对象 | 必须验证 |
|---|---|---|---|
| 理解产品 | 具体问题、能力证据、边界、行动 | 可运行界面、产品图、真实结果 | 访客能找到关键能力及下一步 |
| 连续阅读 | 导语、层级、正文、注释、上下文 | 中文排印、必要图表 | 阅读与目录定位不中断 |
| 选择比较 | 共同口径、差异、条件、价格或限制 | 表格、规格、可选项 | 条件不藏起来，选择可撤回 |
| 查找管理 | 搜索、筛选、结果、详情、状态 | 列表、表格、工作台 | 键盘、空结果、错误恢复 |
| 报名办事 | 适用对象、时间地点、材料、流程 | 时间表、清单、表单 | 字段、校验、提交状态真实 |
| 参观探索 | 主作品、观察问题、关联、来源 | 作品、地图、档案 | 详情可访问、素材归属保留 |

这些是问题类型，不是固定页面模板。混合任务可分层，但必须有主次。

## 方向比较的最低信息

每个方向只需展示足以判断的片段，并说明：

- 信息先后为什么适合这个访客。
- 真实中文标题如何排，主要阅读区在哪里。
- 主对象是什么，是否已有可靠素材。
- 关键动作在哪里，窄屏如何成立。

不能把三张同骨架、同主图、同标题的换色图当三个方向。不要把所有页面自动变成居中口号、三卡片、数字墙、评价、价格与问答的组合。

选择之后保持完整视觉系统：字号角色、间距、对齐、色彩职责与组件状态。不要每一段都重新发明风格；内容有真实转折时才改变节奏。

## 受限改版

改之前记录重要路由、链接、字段名、字段标签、测试钩子、键盘路径、处理结果与必须保留的内容。能运行旧版时先操作一遍，只有截图时明确无法证明原有行为。

区分允许变化的外观和受保护的行为。用户只让修字号，就不要重构状态管理。定位不到行为或现有约定有冲突时先说明，不能自行假定删除也没关系。

改后以相同任务操作，比较结果，而不只是比 DOM 数量。保留失败截图；发现旧版更清楚的地方就吸收，不为维护新版而辩解。

## 只审阅

不修改源文件。每个问题提供路由、视口、状态、元素或内容定位、复现步骤、影响和建议。区分确定性错误、设计风险和需要人工判断的意见。

没有看到或没有执行的内容不做肯定结论。对未知背景的品牌选择，先描述其效果；不能因为用了紫色、系统字体或卡片就判失败。

## 多项目的辨识度

检查近期独立项目是否反复出现同一个首屏骨架、主对象、密度和节奏。记录相似原因，作为下一次探索提示。维护同品牌产品时应优先一致性，不为了避免重复强行换字体和结构。

记录留在项目已有设计文件或本地任务记录，不自动写入全局个人偏好。个别用户的口味不成为公开默认规则。
