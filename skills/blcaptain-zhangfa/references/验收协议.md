# 验收协议

## 状态不可混合

| 机器状态 | 含义 |
|---|---|
| pass | 请求范围已执行，未发现该检查的错误 |
| fail | 有可定位的失败 |
| not_run | 因缺环境或未执行而没有结果 |
| unknown | 已观察但不能可靠判断 |
| not_applicable | 检查确实不适用于这个任务 |

这些状态只对各自范围有效。不要把 unknown 或 not_run 换成“通过”。审美没有确定性的机器总分；未经人类体验的部分标记 `MANUAL_PENDING`。

## 分寸集成

使用经过验证的 `measure-cjk@0.1.0`。先确认本地版本和项目依赖；不静默升级、不自动联网安装。

已有命令示例：

```bash
measure-cjk --version
measure-cjk fonts "Noto Sans SC" --format json
measure-cjk lint http://localhost:5173 --render --format json --out measure-results.json
```

端口和输出路径替换为当前项目实际值。未安装时，经用户任务授权在项目本地安装固定版本，或明确告知当前中文度量尚未运行；也可以显式使用 `npx --yes measure-cjk@0.1.0`，但需要联网且会获取包，不把它说成离线检查。

分寸静态模式面向 HTML/CSS，不能对未渲染 JSX 扫一次就宣称中文页面已验收。React、Vue 等项目优先检查实际本地开发服务或构建产物。渲染模式需要项目本地浏览器驱动依赖与可用浏览器。

保留分寸原始 JSON、退出码、关闭规则和理由。退出 0 可能是没有中文；退出 1 表示发现错误；退出 2 是用法或环境问题。查看受检文件、跳过项与实际覆盖，不只看进程码。

## 章法客观检查器

在项目目录调用技能路径下的脚本：

```bash
node <技能目录>/scripts/check-page.mjs --help
node <技能目录>/scripts/check-page.mjs --url http://localhost:5173 --out evidence/zhangfa
```

`<技能目录>` 是已安装技能的实际绝对路径。脚本从当前项目解析现有浏览器依赖；不悄悄安装。检查远端网址必须显式开启允许远端选项；开始前确认访问和截图属于本任务。

检查器记录截图与 JSON，覆盖部分布局、资源、控件名称和运行错误。复杂背景对比度、完整键盘流程、真实字体逐字命中与全部无障碍条款并未自动覆盖，不得在报告中推断为通过。

`pages[].headings` 仅记录前12个可见横排 `h1/h2` 的实际行片段、计算字号与字体栈；不会自动覆盖其他元素、图示标注或尚未触发的动态反馈。它按浏览器文字范围取得每行，不按汉字数猜断点；字体栈仍不是实际字形来源证明。按任务另选主要动作、导航、图示和操作后反馈，保存其元素、状态与实际文字行或截图，再逐行判断语义。探针的几何成功不等于全页文字或审美通过，不把补充采样扩成自动语义总分。

## 浏览器矩阵

默认检查七种宽度 320、360、390、768、1024、1280、1440，包含320px重排。按任务追加实际断点两侧；不要假装所有交互都在所有尺寸做过。

至少有一条主任务实际操作记录。阅读页可以是目录与注释往返；后台可以是筛选、详情与错误恢复；表单检查输入、校验与明确的提交结果。没有后端时仅确认本地演示行为，不生成真实预约、付款或发送回执。

按受影响范围追加以下压力检查，并写明实际使用的方法；不必让每个局部小修穷尽矩阵：

| 检查 | 操作与判断 |
|---|---|
| 窄屏重排 | 水平中文阅读在320 CSS像素宽检查信息、功能和双向滚动；必要的二维内容局部例外，不能因此豁免整页 |
| 文字放大 | 实际浏览器放大或文字缩放至200%，检查内容与控件；脚本改字号只能算实现压力测试，不能冒充浏览器缩放验收 |
| 用户间距覆盖 | 将行高设为至少1.5倍、段后距2倍、字距0.12倍、词距0.16倍字号，检查是否丢内容或功能；这是覆盖测试值，不是作者默认美学，按文字系统适用项处理 |
| 交互可达 | 键盘走完主路径，确认焦点可见、操作对象未完全被粘性内容遮挡；触屏操作不依赖悬停 |
| 加载与降级 | 首次、加载后及字体或关键资源失败分别看文字、主对象、操作和位移；减少动态效果开启时内容仍可理解 |

键盘、焦点可见及不被粘性元素遮挡需要实际操作。自动可访问名称检查不等于键盘任务已经完成。普通文字对比度通常至少4.5:1，大文字3:1；复杂背景需可靠测量或标未知。点击目标的AA最低要求是24×24 CSS像素并有间距、行内等例外；较大目标有利于触屏，但不能把44像素说成所有目标的AA硬门槛。这里只说明部分验收边界，不构成完整无障碍合规声明。

## 有效截图

记录当前代码版本、URL、浏览器、视口、缩放和内容状态；等待字体与图片的可观察结果。两侧比较用相同内容、相同视口与相同任务状态，按相同锚点取景。

先保存修复前文件及摘要，记录截图锚点和滚动位置；待比较区域实际加载后再取图，避免标题已切换、预览仍是上一页。截图需包含足够上下文解释问题，不截掉关键动作或附带代价。

全页可有不同高度；不缩小其中一版伪造整齐对照。截图不是全部功能证据，截图失败也不是页面必然设计差。重取有效截图时保留失败原因。

## 独立审阅与仲裁

先只给审查者任务、冻结内容、有效产物和运行入口，再看机器报告。按影响列出具体问题；如果机器提示与设计理由冲突，保留双方证据，检查适用范围或误报，不直接把两份清单拼接。

将问题分为阻断操作、影响理解和视觉取舍；逐条提供元素、宽度、实际文字行片段或截图、影响与改动理由，不堆抽象评语。修后复看整体层次与阅读节奏，并检查修补是否损害其他宽度、原文或交互。

独立模型审阅与真实人类盲评分别命名。人类任务测试每人每题只看一种条件，避免学习答案；并排视觉偏好单独开展。

## 公开对比的口径

原始生成、后期审查修复和手工教学示意分别标注。推广精选应说明从哪些样本选择、解决了什么、仍有什么边界；不能把人工修复后的页面替换成“首次生成”成绩。机器规则计数、独立模型意见、人类偏好和业务指标分别报告，没有实测的数据不写提升百分比。

## 最小交付记录

写清变更位置、可检查行为、运行结果、证据、推断、未覆盖项、人工状态与回滚范围。已有项目记录就更新它；小修改不必自动生成一套文档。

规则例外必须有具体范围和理由。修复后重测影响范围；仍有失败就明确保留，不能删除内容、关规则或裁切页面来获得绿色报告。
